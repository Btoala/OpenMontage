# Recovery desk design

Preserve the established paper-and-forest direction. Off-white `#f2f3ef` surfaces, dark forest `#172a29` navigation/text, muted `#536360` text, `#d7ded8` dividers, green `#17654f` actions and lime `#e9f4a5` selected navigation. Amber denotes limited evidence; red denotes a scoped unresolved requirement. Every status is written in text as well as color.

System fonts keep the snapshot independent of external requests. Base text is 16px, headings 25–52px, bounded line lengths, spacing in 8px increments. Dense records use readable 13–14px text with a detail dialog for full fields. Buttons have visible keyboard focus, meaningful names and 44px touch targets. Desktop navigation is a left rail; narrow screens use a horizontally scrollable navigation row. Tables scroll inside their own container. No animation is required.

Overview explains evidence dates and displays counts with clear units: records, recorded byte checks, temporary/inaccessible records and requirements. Counts never claim unique assets or complete backups. Inventory uses project, episode, version, type, evidence and text filters. Recovery gaps show options without action controls. Version groups preserve project/episode association. A method view explains verification and export boundaries.

Inspect overview, record details, empty filters, pagination, both exports and the method view at desktop and narrow sizes. Validate the public synthetic build and private snapshot separately. Do not promote a screenshot, download event, file hash or archive CRC to a full restore or media acceptance claim.
